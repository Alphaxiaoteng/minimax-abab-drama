# 演示视频脚本（2–5 分钟）

> 智谱 AI · 2026 AutoGLM 手机与桌面端侧智能体共创挑战赛
> 目标：让评审在 3 分钟内看懂「痛点 → 架构 → 真机/虚拟实测效果」，并把**容错能力**作为核心卖点打出来。

## 0. 录制前检查（30 秒，务必先跑一遍）

```bash
cd src
python3 run_demo.py                       # 必须末行出现「结果: 全部闭环通过 ✅」
python3 -m pytest tests -q                # 必须 30 passed
python3 run_demo.py --chaos --trace chaos_trace.md   # 必须仍全绿且生成轨迹
```

- 屏幕放大到 125%（终端字号 ≥ 16pt），保证录屏能看清中文。
- 终端配色用浅色背景，保证投屏/压缩后可读。
- 提前把本脚本的关键输出片段打上时间戳，便于剪辑对齐。

## 2. 预置故障注入清单

| 注入方式 | 命令/开关 | 期望现象 |
|---|---|---|
| UI 元素漂移 20px | `--chaos` | 定位仍命中，`at` 坐标与默认不同 |
| OCR/UI 文本噪声 | 场景内置 `noisy=True`（默认开启） | 价格仍被正确解析 |
| 输入框内容被清空 | `--chaos` | 出现 `[chaos] 已注入…`，随后自动重键入并校验通过 |
| 开屏广告 + 权限弹窗 | 场景内置 `popup_on_enter` | 业务步骤前被 `PopupGovernor` 消化 |
| 步骤后才弹窗 | `tests/test_resilience.py::test_popup_after_arbitrary_step_is_absorbed` | 下一步动作前被体检发现并处置 |
| 黑屏（动作前可发现） | 元素与文本双空 | 等 0.4s → `back` → 重启应用 |
| 点击无响应/卡死（动作后才发现） | 动作前后屏幕签名完全相同 | `back` → 累计 2 次重启前台应用 |
| 静止的正常页面 | 不得误判为冻结 | —（不处置，避免误伤） |
| 关键步骤持续失败 | `tests/test_resilience.py::test_critical_failure_keeps_checkpoint_then_resumes` | 落检查点中止，`resume=True` 可从断点续跑 |
| 无 adb / 无 pyautogui | `DEVICE=adb` / `DEVICE=desktop` | 明确的中文降级提示，控制流不中断 |

## 4. 常见录制问题

- **终端中文乱码**：改用 iTerm2/Terminal.app 默认字体，或设置 `LANG=zh_CN.UTF-8`。
- **`run_demo.py` 输出太快看不清**：先跑一次 `--trace` 生成表格文件，录屏时切到文件展示。
- **真机段无法录制**：明确在画面标注「未在本机验证：需连接 Android 真机」，不要伪造成已实测。
- **时间不足**：优先砍 0:00–0:25 与 4:30–5:00，核心段（2:40–3:30 故障注入）必须保留。
