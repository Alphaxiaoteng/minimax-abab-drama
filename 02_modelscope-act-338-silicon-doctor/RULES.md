## 3. 官方赛题与交付物要求

### 赛题详情与考核目标
本次大赛基于 OpenHospital 底座，构建高度拟真的全科诊疗 Arena。这里没有标准单选题，只有 12,000 名鲜活的智能体患者与上千种错综复杂的疾病网络，覆盖多发病、罕见病及复杂共病。这是一场让 "硅基智能体"与"碳基医学生"同台竞技 的临床试炼——评判标准回归医疗本质：问得更准、查得更精、治得更好。

### 交付物形式清单
1. **源码仓库**：规范的 GitHub/Git 仓库（代码整洁、含 Dockerfile / requirements.txt / package.json）。
2. **演示视频 (Demo Video)**：2-5 分钟高保真操作录屏，清晰讲解痛点、架构与实际执行效果。
3. **架构与说明文档**：包含核心业务流程图、核心算法与技术选型理由的 Markdown 文档。
4. **在线体验 / 部署产物**：在线体验链接、小程序体验版二维码或可一键运行的本地脚本。

## 4. 避开红海：核心破局打法与制胜策略

1. 核心破局点：基于 OpenHospital 基座，构建多轮病史问诊、鉴别诊断与用药建议 Agent。医疗垂类壁垒高，参赛队伍极少。
2. 推荐打法：
   - 针对 12,000 名模拟患者，设计循证医学 Prompt 决策树与多模态检验检查结果（血常规、CT报告文本）解释器。
   - 引入安全红线过滤器：严禁幻觉用药剂量，增加「谨慎复核与转诊建议」兜底机制。
3. 交付要求：魔搭线上评测环境提交 Agent 代码与配置，完成真实诊疗场景打榜评测。
4. 评奖优势：参赛队伍少，多数开发者缺少医疗常识；只要问诊逻辑严密、无低级用药常识错误，即可稳拿前排奖励。
