# 演示视频逐镜脚本（目标总时长 3:10，允许区间 2:30–4:00）

> 用途：观猹 × 2026 微信小程序开发大赛「演示视频」交付物。
> 录制建议：微信开发者工具「真机调试」投屏 or iOS 模拟器 + 录屏，旁白提前录好对齐。
> 每条镜头：**时长 / 屏幕内容 / 口播要点 / 证据点**。

---

## 镜头 1 · 痛点开场（0:00–0:20，20s）

- **屏幕**：纯文字动效页——「30 页财报，你读得完吗？」「23 条待办，哪条真的重要？」
- **口播**：信息过载时代，两个高频痛点：长文档读不完、日程列表做不完。做一款**打开就有结果**的 AI 小程序。
- **证据点**：无（建立问题）。

## 镜头 2 · 秒开实测（0:20–0:50，30s）

- **屏幕**：真机冷启动小程序 → 首页 → 点「一页纸快读」，首帧直接渲染出上次缓存的标题与摘要，全程无 loading 转圈。录屏上用开发者工具 Performance 面板或浮层显示 `onLoad → 首帧 setData` 时间戳。
- **口播**：注意首帧——**没有等待网络**。首包只含首页，功能全在分包；`lazyCodeLoading` 按需加载组件；`onLoad` 同一帧同步读本地缓存，内容先出现，AI 在背后刷新。
- **证据点**：**「首屏 X ms 出现缓存结果」**（现场读出 Performance 面板数值，预期 < 500ms，`npm run demo` 中 t0 同步读缓存为亚毫秒级可作为数量级佐证）。

## 镜头 3 · 快读主流程（0:50–1:40，50s）

- **屏幕**：粘贴一段真实感财报长文（≥600 字，可用 `npm run demo` 内置样文）→ 点「开始分析」→ 骨架首帧 → 流式打字机文本 → 结构化卡片：标题、3–5 句摘要、关键数字表（营收 128.6 亿 +23.4%、净利 18.9 亿 +31.2%、现金流 22.3 亿 +18.9%）、风险条目。
- **口播**：Agent 走云开发 AI 的 SSE 流式通道，每一步（思考/生成/工具调用/产出）都映射成可见步骤；模型超时或失败时自动切到内置离线内核，**结果不空白**。同一段文字两次分析结果完全一致，可单测可复现。
- **证据点**：卡片上具体数字与原文对得上；展示「两次运行 structured 全等」的终端截图（来自 `npm run demo` 自检行）。

## 镜头 4 · 断舍离主流程（1:40–2:20，40s）

- **屏幕**：切到「日程断舍离」Tab → 粘贴 13 条含时间词/紧急词/重复项的待办 → 输出：保留清单按紧急度降序 + 删除建议（低价值、重复 82%、转循环提醒三类理由）。
- **口播**：紧急度 = 截止时间 ×2.0 + 紧急词 ×1.5 + 今日锚点 ×0.8 + 重复习惯 ×1.0；删除不是拍脑袋，每条都带可解释理由。
- **证据点**：指着「重复：与 X 相似度 82%」说明算法生成，非模板文案。

## 镜头 5 · 降级演示（2:20–2:45，25s）

- **屏幕**：开发者工具 Network 面板勾选「离线」→ 再次发起快读分析 → 界面照常出完整结构化结果，卡片角标显示「离线分析」。
- **口播**：断网、审核环境、演示现场翻车？不存在。确定性内核是默认兜底，AI 只是锦上添花的增强层。
- **证据点**：`usage.mode=local` 角标可见；对照终端 `npm run demo` 的 `[降级]` 行截图。

## 镜头 6 · 一键验证 + 收尾（2:45–3:10，25s）

- **屏幕**：切到终端，连续敲 `npm run verify`（check + test 全绿）与 `npm run demo` 尾部输出 → 回到小程序展示分享海报卡片 → 定格体验二维码。
- **口播**：仓库自带一键验收：静态校验九条规则 + 单元测试 + 离线演示 + 体积检查，零第三方依赖。扫码即可体验，谢谢大家。
- **证据点**：`checked N files, 9 rules, 0 failures` 与 `node --test` 全 pass 的行；最后 3 秒定格二维码。
